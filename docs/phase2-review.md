## 今回具体化した回路

1. 5V/16MHzクラシックNano互換を想定し、SPIで595を2段接続。OEはGNDに固定してD8は予備に変更。起動データ確定前はHVを許可しない。
2. DS3231のVCC/I2Cは5V。5〜12番N.C.をGNDへ接続し、RST外部プルアップなし。一次電池へ充電回路を設けていない。
3. MCP1700-3002E/TOでJJY用3Vを供給し、入力に100Ω＋10µFのフィルターを設ける。出力の1µFは有効容量で満たす必要がある。TO-92の1=GND、2=VIN、3=VOUTはS33と照合。
4. µA級のJJY出力はHCT125で5Vへ。未使用のHCT125入力を固定し、未使用出力はNC。2個のMPSA42で選局端子を3V領域に引き下げ、起動時はH/H停止とする。選局には論理反転が入る。
5. HVモジュールのSHDNを12V側へ2.2kΩで上げ、MPSA42で動作許可時に引き下げる検討案。停止しきい値・入力電流は出荷版で確認が必要。SHDN停止は出力電荷の即時放電や接触安全を保証しない。
6. USB書込時に5V降圧器との接続を外すJP1と、通常未挿入のHV手動許可JP2を配置。互換機のUSB逆給電は実物回路図で確認する。
7. 各表示子にK155ID1とIN-12Bの接続、個別アノード抵抗、デカップリング、ロジック/HVコネクター、子板側の放電抵抗を定義した。ただしアノード抵抗値と非選択出力保護は未確定。

表示子0〜3は正面から左→右。16bit表示語のbit0〜3=時十、bit4〜7=時一、bit8〜11=分十、bit12〜15=分一として、上位バイトを先に送ればU2へ分、U1へ時を保持する。これは回路上の割当で、ファームウェアの実装・試験は今後行う。

抵抗を介したLDO電源にERCの電源未駆動が出たため、受動フィルター後の電源宣言を追加した。これはR30から5Vを供給することの宣言で、実電圧や電流の安全性を示すものではない。エラー除外で隠していない。

## 電気的な保留

**HV関係は通電できる完成回路ではない。** IN-12Bの動作電圧と電流（R01）、K155ID1の非選択出力60V制約と保護（R02）、昇圧器の出荷版/過渡/連続電流（R06）が未確定。`TBD_R01_ANODE` と `TBD_R07_NEON` を実装値に置き換えていない。

既製降圧器とHV昇圧器は、端子名に基づくインターフェース図。モジュールの端子番号やフットプリントを推測していない。全フットプリントは未割当で、正式部品の調達/寸法確認後に配置する。

電源板の220kΩと子板5枚の1MΩが同時に接続されると、等価放電抵抗は約104.8kΩ。235Vでは約2.24mAを消費するため、Phase 1の放電抵抗1本の見積より負荷が増える。HV負荷は管最大14mA＋ネオン仮1mA＋放電最大約2.24mAに、保護回路等の余裕を加えて再評価し、25mA級の候補を調査する。

子板に追加のHVコンデンサーは置いていないが、分離状態のアノード配線や管の容量の放電経路まで安全を確認したわけではない。総容量と測定点、接触防止を確定するまで固定の放電待ち時間を指示しない。

## 実行した検査

`python3 scripts/check_hardware.py` でKiCad 10.0.8のERC、XMLネットリスト、CSV BOM、PDF出力を実行。回路定義とKiCad出力の全接続393ピンを照合し、資料基準の106ピン対応も確認した。ERCは違反0件、BOMは103件の部品番号・値・出典/保留情報と一致した。

既定ERCで無視される単独グローバルラベル、4方向ジャンクション、SPICEモデル、フットプリントフィルターの4項目はレポートに記録している。これらや未割当フットプリント、絶縁、部品定格、実測を「検査済み」としない。

共有寸法の検査、生成定数の一致、KiCadでの機械基板6枚の読戻しにより、外形・板厚・穴座標/径を照合した。機械基板は部品と配線を含まないので、これを回路図と基板のネット整合性検査の代わりにはしない。回路PCBのDRCはまだ未実施。

OpenSCAD 2021.01の公式配布DMGを取得し、公開SHA-256 `4e4568e19992636ba497c04bc2238399c92314fcb7bf75dc3632aa623ca3635e` と照合。一時マウントしたCLIで、警告を失敗扱いにして組立CSG、前後板SVG、木枠/HVカバーSTL、組立PNGを出力した。OpenSCADは常設インストールしていない。出力・ログは `build/enclosure/openscad-check.json` に記録。

管ピッチ不足、基板外の穴、HV近傍のアンテナ、パネル外の電源穴を注入した4ケースで、共有寸法検査が失敗することを確認した。製造承認を要求する `scripts/check_hardware.py --require-release` も現状では終了コード1を返し、通常の資料整合性検査の成功と区別する。
