## 金額の意味

`docs/bom.csv` の `observed` は税込販売表示、`budget` は見積未取得の予算枠。技術資料への参照は価格の根拠を意味しない。JJYの準備中表示やアダプターの安全証憑未確認も別の状態として記録している。

集計は資料整合性スクリプトで再計算する。外装、工具、測定器、予備管、再設計費用は未算入。K155ID1に追加保護が必要になった場合も増額する可能性がある。15,000〜20,000円は目標であり、達成した予算ではない。

| 集計区分 | 下限の予算枠 | 上限の予算枠 |
| --- | --- | --- |
| 電子回路・アダプター・初回裸基板 | 15,315円 | 26,325円 |
| 送料等 | 1,000円 | 2,500円 |
| 合計 | 16,315円 | 28,825円 |

予算目標に収まる可能性はあるが、現時点の幅では超過する。特に管とソケット、HVモジュール、RTC、分割基板の送料を見積で絞る必要がある。安全部品を削って帳尻を合わせない。

## 実行した資料検査

- `python3 scripts/check_phase1.py --output build/phase1-check.json`：成功。32件の出典と21行のBOM、必須資料、リンク、出典参照、金額区分を検査。取得済みキャッシュがある場合は記録のSHA-256とも照合した。
- `python3 -m py_compile scripts/inspect_environment.py scripts/fetch_references.py scripts/check_phase1.py`：Python構文検査に成功。
- PDF取得は16件を対象に11件を保存、5件は失敗。S05/S16はHTTP 403、S06は通信タイムアウト、S17は証明書期限エラー、S18は名前解決失敗。失敗を修正済みとして扱っていない。
- 通常の資料検査は未取得項目を報告しつつ続行する。`--require-downloads` は全PDF取得を要求する厳格モードで、現状では失敗するのが正しい。
- 厳格モードの終了コード1を確認。作業ディレクトリを `/tmp` に変えて資料検査を実行しても成功した。新規資料・スクリプトは `git diff --no-index --check` で空白エラーがないことを確認した。
- この記録のコマンドはmacOSで実行。両OS対応はスクリプトの実装方針であり、Ubuntu上で成功したという記録ではない。
