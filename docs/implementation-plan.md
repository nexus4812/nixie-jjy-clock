# Phase 2以降の具体的な実装計画

## Phase 1からの引き継ぎ

最新状態は `git show 4e38a86:HANDOFF.md` と [control-r1記録](control-board-r1.md)。KiCad 10.0.8導入済み。全体回路図111部品、低電圧制御板54部品の候補配置/配線、OpenSCADケース案を作成した。制御板のERC/DRC/未配線/等価性の問題0をmacOSで確認。下記は全体の計画で、記載した全工程が未着手という意味ではない。

次はR01/R02/R06のHV動作条件・ドライバー保護、R03/R04/R05の個別販売品/現物照合を優先する。ケース部品高さ・固定具・ハーネスは未確定。Arduino実装とUbuntu検査は未実施。MCP追加設定は現在不要。

## Phase 2：回路設計

1. 管/ソケット、Nano互換、JJY、HVモジュールの個別販売品を特定し、比較見積と資料をBOMへ反映。受信モジュールが入手できなければ40/60kHzの代替を資料付きで再選定する。
2. R01/R02を解決するため180Vと200V付近の動作条件、K155ID1の非選択端子・クランプ・消灯方法を比較し、負荷/熱/故障状態を計算する。現物評価が必要な点は人間向けの単管試験手順にする。
3. KiCadの導入版・ライブラリを記録。編集経路は実際に使えるGUI/API/MCPを評価し、存在確認した機能だけを使う。
4. 電源/保護、MCU/595、RTC/電池、JJY/変換、1桁表示、コロン、ボタンのシートを作成。各端子表のレビューを通す。
5. 低電圧とHVをシート/ネット名/説明で識別し、共通GNDであることも明示。電流制限・放電・故障時・初期OFFの計算書を確定する。
6. ERCとPDF/ネットリスト出力を実行し、警告ごとに原因と判断を残す。IC電源/未使用入力/DS3231 N.C.の接地を確認する。

成果物予定：`hardware/control/`、`hardware/display/`、`hardware/colon/` のKiCadプロジェクト、プロジェクト内ライブラリ、確定ピン表、定格表、計算書、ERC記録。完了条件は回路の接続と部品定格がレビュー可能で、未解決事項が具体的に示されること。実物の安全動作を意味しない。

## Phase 3：基板設計

1. 人間が現物を測定し、管とソケット・Nano・JJY・HV・コネクターの図面を照合。AIはシンボル/フットプリントとの対応を独立照合し、1:1印刷確認を準備する。
2. 独立表示子の仮治具を使い、全4管の間隔、中央余白、高さ、保守スペースを検討。ケース外形/穴はこの時点でも仮を明示する。
3. HV/LV境界、ソケット近傍、カバー、取り付け金属の離隔を設計し、根拠付きのDRCルールを作成する。共有GNDのため通電時の電位・故障経路もレビューする。
4. JJY受信ユニットを離し、電源リターン、昇圧ループ、デカップリング、テストポイントを配置して配線する。
5. 回路図から基板へ更新し、全ネット/ピン、未配線、部品番号、BOMを照合。DRCと目視レビューを別々に実施する。
6. JLCPCBの最新条件と見積を確認。条件案は2層FR-4、1.6mm、1oz、一般的な加工条件を優先するが、枚数・外形・穴径・面付けは現物とケース案を踏まえて決める。

成果物予定：配置/配線済み基板、正面/裏面PDF、フットプリント照合記録、DRCルールとレポート。完了条件は電気接続、加工性、安全上の離隔、現物取付が評価できること。穴や外形が仮なら発注用としない。

## Phase 4：Arduinoファームウェア

1. Arduino AVR Boards、書込対象のFQBN、ブートローダー、RTCライブラリの版を固定。`firmware/nixie_clock/nixie_clock.ino` を入口にしてIDEでも開けるようにする。
2. Arduino依存部と、JJYパルス分類・フレーム検証・日時計算・状態遷移・4桁BCD変換を分離する。RAM 2KBの固定長バッファ、動的確保なしを基本にする。
3. JJY入力の極性を正規化し、エッジ時刻から幅と秒間隔を測る。NICT定義の0.2/0.5/0.8秒を根拠に、受信遅延・ジッターを含む許容窓を実測後に決定する。
4. マーカー位置、BCD各桁の妥当性、時分パリティ、通算日、閏年、曜日、年、連続2フレームの整合を検証する。±5msは送信側仕様であり、そのまま受信窓にしない。
5. 毎時15/45分の呼出符号フレームと、うるう秒実施付近の特殊フレームは初版では採用を保留して再同期する方針。無効データでRTCを上書きしない。
6. フレームは先頭M時点の時刻を送るので、完了した瞬間にその時刻の秒0を書き込まない。次の分境界までの経過を追跡し、境界で補正・RTC読戻しを検証する。
7. RTC_ONLY/SYNCED/STALE、有限の再受信と局切替、コロン、手動日付/時刻設定、任意の消灯・数字巡回を非ブロッキングで実装。I2C異常/RTC無効時は状態表示し、処理を固めない。
8. 擬似エッジ/フレームでホスト試験とスケッチのコンパイルを実行。macOS/Ubuntuで同じ入力から同じ結果を得ることを確認する。

成果物予定：Arduinoスケッチ、ハードウェア依存の薄いドライバー、純粋ロジック、擬似受信フィクスチャ、固定された開発環境・書込手順。完了条件は異常データを拒否し、受信不能でも有効RTCの時計が継続すること。実受信と実管の検証は別に実施する。

## Phase 5：検査と製造準備

1. KiCad版/ライブラリ版とGitの版を記録し、ERC、DRC、回路図↔PCBのネット照合、BOM/部品番号の照合を再実行する。
2. 最新の[JLCPCB加工能力](https://jlcpcb.com/capabilities/pcb-capabilities)で線幅/間隔、穴/ランド、銅箔-外形、板厚、スロットを照合。今回同ページは動的表示中心で加工限界の数値確認は未完了。製造最小値をHV安全距離と混同しない。
3. Gerber/Excellonと外形/穴を出力し、別ビューアーで表裏・原点・層・寸法・穴を検査。ファイル一覧、SHA-256、生成コマンド、製造条件をリリース記録へ残す。
4. 実装順序、部品極性、はんだブリッジ、電源間抵抗、電池の非充電、カバー/ハーネス/絶縁を確認する作業票を作成する。
5. 入力電流制限、低電圧のみ、RTC/表示データ、HVダミー負荷、単管、4管、JJYの順に段階通電。HV停止後の放電、管抜去、リセット、USB逆給電、温度も別に測定する。
6. 人間による試験結果、問題点と改版理由を残し、初回試作品の修正を経てリリース判定する。

成果物予定：製造ZIP、確定BOM、調達表、実装図、通電前/実装後/動作試験手順、実測記録の書式。実機安全性の確認が残る場合は「製造出力済み・実機未検証」と明記する。
